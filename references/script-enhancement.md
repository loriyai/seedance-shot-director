# 分镜前剧本审阅 V1.23

## 范围

本流程在用户本次指令选择“轻度剧本审阅”时启用。审阅只做三件事：

1. 语法与错漏检查：多字、少字、错别字、标点错误、语序与指代错误，以及会阻断执行的逻辑冲突。
2. 台词换行规范化：按 [dialogue-normalization.md](dialogue-normalization.md) 把同一话轮内部的排版换行替换为标点。
3. 机械派生、覆盖差分与剥壳：整篇稿件由脚本从上一版派生，交付前过覆盖差分闸门。

审阅不改写剧情，也不做表演设计：不细化动作、不加副反应、不新增道具互动、不调整镜头节拍，不新增独立反应节拍，不为了让文字“更精彩”发明事件、台词、动机、关系、能力、道具、冲突结果或世界观事实。审阅稿里不得出现表演类标记（如动作细化、新增动作）。

本文只补充审阅阶段操作；来源、台词与时空硬边界直接执行 [core-invariants.md](core-invariants.md)。审阅路径默认不读情绪、摄影、构图或空间专项文件；只有存在影响基本逻辑的 P0 空间疑点时，才读对应专项文件。

## 版本语义

- `V0`：用户原始文本，永不覆盖。
- `V0.x`：用户明确确认的错漏字、非换行规范化的标点、说话人或独立编剧修订。一次确认中的多项文字修订合并为一版；仅话轮内部换行的确定性规范化不单独创建 `V0.x`，原版仍保持不变。
- `R1、R2…`：带标记审阅稿。首次审阅、重新优化或实际正文变化时才新建；同内容重试复用当前 R 版本。
- `C1、C2…`：用户发送“确认剧本”后，从当前 R 稿机械清理标记得到的干净分镜来源。

“重新优化剧本”必须重读当前原版基线，不在旧 R 稿上叠加。“使用原版剧本”锁定当前最新 `V0.x`（无则 `V0`）；只有“使用最初原版 V0”才回到初始输入。未选原版或未确认审阅稿时，不拆生成块。

## 一次扫描

### 机械派生：不手抄整篇文本

审阅过程产出的每一份完整稿件都由脚本从上一版派生，不用人工转录。把来源路径、动作说明的最小替换和空格/疑点标记写成一份编辑清单 JSON，一次生成并自检：

```text
python -B scripts/derive_review.py --source <锁定来源> --edits <编辑清单.json> --output <审阅稿.md>
```

```json
{
  "title": "审阅稿 R1（基于原版 V0）",
  "line_edits": [{"old": "原样整行", "new": "修正后整行", "marker": "🟨【文字修正：原“……”】"}],
  "space_notes": [{"line": "原样整行", "note": "🟥【文字疑点：……；未经确认未删除】"}]
}
```

`derive_review.py` 在同一遍里完成：话轮内部换行规范化、清单内原位替换与标记、覆盖差分闸门，并拒绝覆盖已存在输出；`old` 找不到唯一整行、或差分出现缺失/新增/调序时报错且不写文件，省掉手工转录与写出后才发现漏行。

其余约定如下：

1. 审阅稿正文按来源顺序逐行生成，只在本行做原位替换或标记，不重写相邻行、不跳过任何一行。
2. 交付前跑覆盖差分闸门：

```text
python -B scripts/check_source_coverage.py --source <锁定来源> --draft <审阅稿> --narration
```

对白必须逐段一致（顺序、字数、标点、说话人归属范围内）；出现缺失、新增或调序即停止交付并修复。`--narration` 会列出在稿件中找不到对应文字的原动作句，用于逐条确认审阅没有吞掉来源节拍。

3. 用户确认后用脚本剥壳，不手写干净稿：

```text
python -B scripts/strip_markers.py --review <当前R稿> --output <干净确认稿>
```

剥壳只删除版本标题、彩色标记、疑点说明与结尾操作清单，并自检对白未变；输出存在时拒绝覆盖。剥壳稿入库前再跑一次覆盖差分。

漏句、断行、半截文件都由此挡在交付之前；脚本报错不得绕过。

### 扫描与侧车

先对当前锁定片段运行一次：

```text
python -B scripts/prepare_source.py --source <来源文件> --output <项目侧车JSON>
```

它在终端只输出来源摘要、数量、诊断分级计数和至多 8 条样例；其余诊断只报截断数量。项目侧车保存全部诊断、可靠的规范化话轮、说话人/类型/行号；对“动作行后直接写引号”等无法机械确认说话人的格式，另存 `unresolved_utterances` 的完整正文与最多两行邻近上下文，不丢台词也不擅自归属。只在需要某话轮时读对应记录，不把长文全量 JSON 注入上下文。编译阶段仍会独立执行硬检查。

随后对完整片段从头到尾做一次顺序语义扫描，在同一份中间结果中同时完成：

1. 记录来源句序、说话人、声音类型、事件结果、时空和关键道具，形成来源保护映射。
2. 按 [dialogue-normalization.md](dialogue-normalization.md) 得到规范化话轮与合法换行边界，同时标记疑似多余空格。`unresolved_utterances` 只在本次语义扫描中结合上下文解决一次；不能唯一归属时列 P0，不猜说话人。确认后的结果直接复用于分镜，不重新解析。
3. 逐行检查语法、错漏、语序、指代与逻辑冲突，只记录需要标记的问题，无问题的行保持普通文本。
4. 只记录例外：上下文才可推定、必须串行、制作假设、未知项或 P0 疑点。
5. 就地生成需要审阅的标记；话轮内部换行规范化直接写入审阅正文，不逐处标记或解释。扫描结束后只做一次完整硬复核：台词拼接、声音身份、句序、事件结果、异常空格标记和 P0。不再按每个维度全文重扫。

局部修改仅复核改动范围、相邻一至两句和受影响的保护项；其余内容由精确替换和摘要保证未变。只有影响全局因果或更换基线时扩大复核范围。

## 可修改项

审阅只处理下列问题，命中才动文字，且一律原位替换，不新增句子：

- 动作说明中唯一明确的错别字、多字、少字、标点错误：做最小修正并标 `🟨【文字修正：原“……”】`。
- 动作说明中主语与原意唯一的语序/指代问题：做最小整理并标 `🟨【表达调整：原“……”】`；有两种合理解释时只列疑点。
- 台词、旁白、OS 与独白中的疑似错误不自动修改，紧邻标 `🟥【文字疑点：……；因口播原文锁定，暂未修改】`。
- 扫描引号内首尾空格、连续多个半角空格、Tab、全角空格、中文字符之间或中文标点旁的异常空格；指出位置或数量，不静默删除。外语词组、缩写、数字、型号及用户格式所需单空格不报。
- 人物位置、道具归属、时间线、因果、说话人、行动目标或结果冲突标 `🟥【逻辑疑点：……；未擅自修改】`。影响身份、目标、信息顺序、关键道具、时空或冲突结果的疑点是 P0，即使收到“确认剧本”也先解决。

用户确认文字、空格或说话人后，用 `🟨【用户修订：……】` 标记，同批写入一个新 `V0.x`，不再保留为红色疑点。

## 不做的事

- 不把原文已有动作、表情或姿态展开成更细的表演描述。
- 不给台词配新动作、新反应节拍或新道具互动。
- 不调整动作顺序、节拍时长或镜头设计，这些属于分镜阶段的规划职责。
- 台词改写、冲突或结构调整只在审阅正文外给具体编剧建议，获准后才进入 `V0.x`。

## 审阅输出与命令

可搜索标记只使用：

- `🟨【文字修正：原“……”】`
- `🟨【表达调整：原“……”】`
- `🟨【用户修订：……】`
- `🟥【文字疑点：……；因口播原文锁定，暂未修改】`
- `🟥【逻辑疑点：……；未擅自修改】`

话轮内部换行替换为逗号或拼接已有标点时，审阅稿只显示规范化后的台词，不添加标记、原文对照或逐项变化说明；来源行号与换行映射留在后台供校验。疑似空格、错字及非确定性标点问题仍按上面的疑点/修订规则处理，不借换行规范化名义静默改写。

首次审阅和明确“重新优化”输出完整稿，标题为 `审阅稿 Rn（基于原版 V0.x）`，基线号写实际值。未改变原文保持普通文本。审阅稿可简列变化摘要，不以修改数量为质量指标。

完整稿以文件交付，聊天里只列变化点、疑点与影响判断，不在聊天内重复贴全文；用户明确要求逐字展示时再展示该文件，不由模型另写一份。结尾说明以下四个操作：

1. 指定段落做局部修改。
2. 发送“确认剧本”，清理当前稿并立即继续分镜。
3. 发送“重新优化剧本”，从当前原版基线重做。
4. 发送“使用原版剧本”，忽略审阅稿并直接分镜。

局部修改用 `review-patch` 精确替换指定原文，保留未指定内容；展示变化段、最小上下文、基于哪个版本及最新完整文件。用户只说“不满意”而无法确定范围时，再请其指定段落或期望。

“确认剧本”先检查 P0；通过后保留已确认的审阅正文，删除彩色标记、对照说明、疑点说明、版本标题和操作提示；未经授权改写的台词仍与基线一致。将干净稿锁定为分镜来源，然后直接进入分镜预诊断。
