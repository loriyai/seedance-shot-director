# 资产列表规范

## 目标

资产列表是可供图像生成模型建立 Seedance 所需人物、场景和道具素材的基础描述，不是完整美术设定集，也不是视频分镜提示词。描述使用中文并保持适度概括，给出生图所需的身份、外观、用途和辨识特征即可。

## 后台建档范围

无论用户选择是否输出资产列表，都只先复用 [long-script-index.md](long-script-index.md) 的轻量全局索引保存必要资产指针；当前场次才补临时状态、具体站位、动作路径与机位细节，不预先展开全剧执行档案：

- 可识别人物只记 ID、别名、身份、原文明示的稳定特征和来源位置，不先写完整外观段落。
- 场景只记场景 ID、地点/空间边界、顺序和来源范围，不先写长场景描述。
- 只登记推动剧情、跨场延续或需要辨识的关键道具，以及连续性所必需的人物、场景、道具关系。
- 用户已提供的 `@素材`精确名称、绑定对象和可复用状态版本。

完整剧本接收后，必须询问用户是否需要把资产列表输出到前台。选择“否”时保留上述轻量资产指针，不展开完整人物、场景和道具描述；只有用户明确要求完整资产清单，才按下文补做全剧完整性核对、分类和可交付描述。配置完成前不得开始片段分镜生成。

## 输出类别

用户提供 `@素材`或剧情出现需要跨镜头锁定的服装、伤势、年龄阶段和道具状态时，同时按 [asset-binding-and-screen-text.md](asset-binding-and-screen-text.md) 建立绑定，不改写素材名称。

### 人物资产

进入完整资产清单输出时，人物资产覆盖全剧中可识别的主要人物和有稳定身份的群体角色。每个人物用一段简洁描述，优先包含三至五项：

- 年龄层或身份
- 身材或体态
- 发型、脸部或身体辨识特征
- 固定服装、配饰或标志性物件
- 性格或常见行为特征

区分“核心特征”和“剧情状态”时，不要把换衣服、受伤、沾灰等临时变化误建成新人物。剧本明确写出的特征必须保留；剧本没有依据的发色、瞳色、品牌、纹身和具体年龄不要擅自固定。

### 场景资产

场景资产按地点和空间区域描述，不加入视频风格、美术风格、光线、色彩氛围、景别、运镜或镜头语言。每个场景至少包含：

- 明确地点和空间类型
- 能识别该地点的基本结构
- 剧情必须存在的主要设施和道具
- 反复出现或对空间识别有帮助的固定物件

场景描述只保留对生图有帮助的内容。时间、天气和临时动作属于分镜信息，不默认写入固定场景资产；只有当它们是场景长期不可分割的设定时才保留。

### 道具资产

道具不按“出现次数”单独判断，综合考虑剧情作用、视觉辨识度、人物绑定关系、是否需要动作展示，以及跨镜头保持一致的必要性。

#### A类：独立生成资产

满足以下任一条件即可列入独立道具列表：

- 推动剧情或揭示身份、关系、信息。
- 在多个场次反复出现，或属于某个角色的标志性物件。
- 被拿起、使用、展示、打开、撕毁、捏变形、损坏或成为笑点。
- 需要特写、明显视觉动作或后续镜头保持外观一致。
- 形状、材质、颜色或结构对剧情理解很重要。

描述至少包含外观类别、主要形状或尺寸、材质或颜色、明显识别点和剧情用途。普通物件如果后来承担以上功能，应升级为 A 类。

#### B类：写入场景，不单独生成

场景成立或构图必需，但没有独立生成必要的设施和普通物件，写入对应场景描述，不列入独立道具清单。

#### C类：通常不列出

一次性出现、无剧情作用、无固定外观要求、不会被重点展示且不影响场景识别的普通小物件通常不列出。它们只有在成为关键动作、笑点、线索或连续性对象时，才转为 A 类或 B 类。

## 输出格式

用户明确选择全剧资产列表后，仍完成全剧人物、场景、相关道具的完整性核对和概括描述；两层建档不缩减用户要求的清单，只推迟未处理场次的执行细节。然后输出：

```text
资产列表

一、人物资产
人物名：概括性身份、体态、外貌辨识特征、固定服饰或配饰、性格/行为特征。

二、场景资产
场景名：地点、空间结构、必须存在的主要设施和道具、固定识别物件。

三、独立道具资产
道具名：外观、材质或颜色、明显识别点、剧情用途。
```

不输出 B 类和 C 类的独立条目；B 类内容必须已经写入对应场景描述。资产列表不加入视频风格、美术风格、光线、色彩氛围、景别、运镜、镜头语言或生成块提示词。

来源修订后增量更新资产关系。每项区分原文明示、上下文可确定、制作设定与未知；用户已选低风险制作设定可稳定复用，但不得冒充原文事实。稳定声线与实际音频参考另存项目配置，文字资产描述不承诺精确同声。
